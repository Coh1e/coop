# Coop 已确认的设计范围

本文件记录 2026-10-25 设计讨论中人类已确认的产品边界；执行状态见 GitHub Issues。具体数据格式和技术方案仍待调查与确认。

- 首要场景是接管现有 Scoop 安装，优先原地保留软件、持久化数据和路径，避免重新下载与安装。
- 接管前检查；允许渐进接管，全部安装可查看，只有通过检查的包可更新或卸载；未接管的包继续运行。迁移后由 Coop 独占管理，不承诺与 Scoop 交替写入同一状态。
- 保留迁移前状态备份和失败恢复路径。部分可管理不等于整个迁移已完全兼容。
- 用户无需预装 Git、7-Zip；允许评估内部集成库。特殊包需要外部工具时，安装前明确说明，不静默安装。
- 基础操作不启动 PowerShell；真实 Manifest 需要脚本时使用明确的脚本执行路径，不能静默忽略。
- 兼容承诺基于经过验证的行为子集，分开记录能读取、能生成计划、生命周期已验证。
- 性能优先级：本地查询；检查更新与 bucket 更新；安装过程。所有指标需实测。
- 软件被占用时不强制结束程序：能安全并存并切换则继续，否则保留旧版本并说明重试条件；首版不做后台等待升级。
- 保持 C++20、Windows 与 Adapter → IR → Plan → Executor 边界。每个抽象由当前真实包需求支撑，不为 Hypha 预先建设通用调度、跨平台或 SDK。

- Git 仓库操作直接使用可由 C++ 调用的库，不要求安装 git.exe；不再将 GitHub ZIP 快照作为首选同步方案。libgit2 为首选候选，具体版本、链接方式和构建配置须验证。
- 原地保留软件与持久化数据，Coop 单独保存管理状态，包括接管资格、操作进度和恢复信息；保留原始 Scoop 安装记录作为迁移依据，不要求 Scoop 理解后续全部状态。
- `search`、`info`、`list` 始终读取本地数据；`install` 使用当前已同步的 Manifest，不隐式刷新 bucket。仓库更新由明确命令触发，可显示上次同步时间。
- Coop 控制的文件、命令入口和状态操作必须可恢复；任意安装脚本造成的外部改动不承诺自动回滚。脚本失败时保留日志与恢复信息，明确报告实际状态，不宣称已完整恢复。
- 首版管理当前用户的安装；系统级安装可检测和列出，但暂不接管。
- 更新成功后默认保留旧版本，由显式清理命令删除。切回旧程序与恢复旧数据分别处理，不承诺持久化数据自动回退。
- 首版支持当前版本和本地已有旧版本的管理；暂不从远端 Git 历史查找本机从未安装的版本。无法取得指定版本时明确失败，不猜测下载地址。
- 普通卸载保留 Manifest 声明的持久化数据；彻底删除使用独立、明确的选项，执行前列出删除范围。脚本自身的删除行为须按实际兼容情况说明，不能声称所有外部数据都受 Coop 保留规则保护。
- 默认阻止卸载被其他已知包依赖的软件，并列出依赖方；不自动连带卸载，也不自动清理疑似无用依赖。关系以已保存的 Manifest 为依据，不推断用户项目或自定义脚本的依赖。
- 首版支持公开 HTTPS Git 仓库及本地 bucket，不限于 GitHub；已有私有或 SSH bucket 保留本地查询能力，首版暂不联网更新，并明确提示原因。
- 首版逐步开放经过真实样本验证的脚本上下文与辅助函数；接管检查覆盖后续更新和卸载所需能力。已知缺少必要能力的包暂不接管，脚本能启动不代表兼容已验证。
- 接管、安装、更新和卸载都支持单独预览；预览不执行安装脚本、不修改安装状态，列出包、版本、下载、命令入口、持久化目录、脚本及无法预知的副作用。实际执行前重新检查计划依赖的状态。

产品边界已完成本轮确认；实现提案、待调查事项和验收路径见 [首版设计草案](architecture.md)。相关研究见 [Git 与 goop 调查](research/git-free-buckets.md)。
