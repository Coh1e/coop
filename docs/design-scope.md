# Coop 已确认的设计范围

本文件记录人类已确认的产品边界。2026-10-26 复核已整理为 [正式规格 #21](https://github.com/Coh1e/coop/issues/21)，执行状态见 GitHub Issues；具体数据格式和技术方案由后续任务细化。

## 2026-10-26 目标复核

- 交付目标是 Scoop 生态中的原生协作客户端：共用现有安装与状态，日常查询、安装、更新、卸载、入口与数据持续可用，用户可以先后交替使用 Coop 与 Scoop，无需迁移或独占接管。任务票关闭、测试通过或少量样本跑通不构成产品交付完成；未完成能力仍是待办，不通过改写“不支持范围”宣布完成。
- 官方 Main、Extras 是目标兼容范围；用户当前实际安装的软件集合是第一批硬验收清单。按软件管理机制实现通用能力并持续核对覆盖缺口，不使用固定包或固定脚本文本白名单定义目标兼容性。具体例外必须说明并由人类认可。
- 没有安装 Scoop 的机器也能直接使用 Coop：初始化标准 Scoop 布局与兼容记录，后续 Scoop 可以直接识别；核心不要求预装 Git、7-Zip。脚本兼容组件优先复用 Scoop 的实现，避免另建行为不同的辅助函数体系。
- Manifest 脚本由真实 PowerShell 执行，提供与兼容基准一致的 Scoop 上下文、辅助函数和生命周期顺序；基础下载、校验和解压继续使用 C++。执行前说明必要脚本、外部工具与权限；脚本失败正确传播，不承诺自动回滚任意外部副作用。
- 包声明的用户级 PATH、环境变量和快捷方式按 Scoop 语义管理，不再仅限于命令启动器的子进程。卸载前核对归属，只撤销 Coop 负责的变更并保护用户后续修改；系统级操作不默认开放。本条是产品行为目标，不构成修改当前宿主机真实环境的执行授权。
- 人类选择直接使用本机现有 Scoop 环境进行后续真机验收，不再以隔离环境或专用测试根作为前提；工程依赖、缓存与日志仍留在项目内。此决定替代早期“只在隔离根验证”的验收边界。共用安装根、bucket、软件、持久化数据、入口和安装记录；两工具可以先后交替管理，不承诺同时写入。详见 [共用状态决策](adr/0002-share-scoop-state.md)。实现已获授权，真机软件变更按各执行票的记录范围与证据逐项进行；R01 为只读盘点，R03 起按票执行有界的真实安装、更新与卸载。
- 2026-10-26 已发布正式规格，后续任务按 Issue 原生阻塞顺序执行。既有原型报告保留为历史实现证据，不作为缩小上述目标的依据；任务票关闭或测试通过仍不自动代表产品门槛完成。
- IR 与执行引擎仍是长期资产：Scoop Manifest 经 Adapter 转成与来源格式、Windows API 和具体执行器解耦的包管理 IR，再经验证与计划生成交给执行引擎。后续其他 Package Adapter 应能复用；为 Hypha 的 Resource / Operation / Job 留出自然演进空间，但不提前实现其分布式、通用调度或 SDK。

## 既有边界

- 首要场景是直接共用现有 Scoop 安装，保留软件、持久化数据和路径，避免为切换客户端重新下载与安装。
- 操作前检查实际安装事实与当前能力，具体缺口明确报告并继续补齐；不按安装由哪个客户端创建或是否执行过接管来设置管理资格。
- 保留操作前必要证据与失败恢复路径。部分操作通过不等于整体行为兼容已完成。
- 用户无需预装 Git、7-Zip；允许评估内部集成库。特殊包需要外部工具时，安装前明确说明，不静默安装。
- 基础操作不启动 PowerShell；真实 Manifest 需要脚本时使用明确的脚本执行路径，不能静默忽略。
- 兼容性报告分开记录能读取、能生成计划、生命周期已验证；已验证范围是证据状态，不能代替上文的目标兼容范围。
- 性能优先级：本地查询；检查更新与 bucket 更新；安装过程。所有指标需实测。
- 软件被占用时不强制结束程序：能安全并存并切换则继续，否则保留旧版本并说明重试条件；首版不做后台等待升级。
- 保持 C++20、Windows 与 Adapter → IR → Plan → Executor 边界。每个抽象由当前真实包需求支撑，不为 Hypha 预先建设通用调度、跨平台或 SDK。

- Git 仓库操作直接使用可由 C++ 调用的库，不要求安装 git.exe；不再将 GitHub ZIP 快照作为首选同步方案。libgit2 为首选候选，具体版本、链接方式和构建配置须验证。
- 显式 `bucket add/update` 直接维护 Scoop 共用的 `<根>/buckets/<名称>` Git 工作树：首次克隆、后续在 `.git` 内增量 fetch 并原地前进；保留实际分支、固定 revision、辅助资源和本地修改。本地修改或不支持的目标树在写入前拒绝，不自动 reset/clean。详细契约见[共用 bucket 的直接刷新](shared-bucket-support.md)。
- Scoop 兼容的安装记录与实际文件是共用管理的依据；Coop 可保存附加缓存、操作进度与恢复信息，但不维护独占接管资格。Scoop 改动后重新识别状态，不把缓存失效当成包失去管理资格。
- `search`、`info`、`list` 始终读取本地数据；`install` 使用当前已同步的 Manifest，不隐式刷新 bucket。仓库更新由明确命令触发，可显示上次同步时间。
- Coop 控制的文件、命令入口和状态操作必须可恢复；任意安装脚本造成的外部改动不承诺自动回滚。脚本失败时保留日志与恢复信息，明确报告实际状态，不宣称已完整恢复。
- 首版管理当前用户的安装；系统级安装可检测和列出，但暂不管理。
- 更新成功后默认保留旧版本，由显式清理命令删除。切回旧程序与恢复旧数据分别处理，不承诺持久化数据自动回退；`coop reset <包名>@<版本>` 只用本机保存的 Manifest、安装记录与实际产物回退程序，不重跑 Hook/安装器，持久化链接原地核对复用。
- 首版支持当前版本和本地已有旧版本的管理；暂不从远端 Git 历史查找本机从未安装的版本。无法取得指定版本时明确失败，不猜测下载地址。`cleanup` 预览列出 `delete_scope`/`keep_scope`，只删除已记录、摘要未变、非当前且不受恢复保护的目录。
- 普通卸载保留 Manifest 声明的持久化数据；彻底删除使用独立、明确的选项，执行前列出删除范围。脚本自身的删除行为须按实际兼容情况说明，不能声称所有外部数据都受 Coop 保留规则保护。
- 默认阻止卸载被其他已知包依赖的软件，并列出依赖方；不自动连带卸载，也不自动清理疑似无用依赖。关系以已保存的 Manifest 为依据，不推断用户项目或自定义脚本的依赖。
- 首版支持公开 HTTPS Git 仓库及本地 bucket，不限于 GitHub；已有私有或 SSH bucket 保留本地查询能力，首版暂不联网更新，并明确提示原因。
- 脚本能力以真实 PowerShell 和 Scoop 辅助函数的行为兼容为目标，真实样本用于验证通用能力，不定义脚本文本白名单。操作检查覆盖更新和卸载所需能力；已知缺口继续作为待办，脚本能启动不代表兼容已验证。
- 安装、更新、卸载、清理等修改软件状态的操作支持单独预览；预览不执行安装脚本、不修改安装状态，列出包、版本、下载、命令入口、持久化目录、脚本及无法预知的副作用。实际执行前重新检查计划依赖的状态，不再要求先执行接管。

产品边界已完成本轮确认，正式行为与验收以 [规格 #21](https://github.com/Coh1e/coop/issues/21) 为准。[首版设计草案](architecture.md) 保留作历史背景；其中冲突的独占接管等描述不再作为实现依据。相关研究见 [Git 与 goop 调查](research/git-free-buckets.md)。
