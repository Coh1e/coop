# 使用内嵌 Git 库管理 bucket

用户选择通过 C++ 可调用的 Git 库获取和更新 bucket，避免强制安装 git.exe，同时保留增量传输与 Git 对象读取能力。GitHub ZIP 快照不作为首选同步方案；goop 的快照路径仅作对照依据。

首选候选为 libgit2，在 Coop 内部以少量 C++ RAII 类型管理其 C API 资源，不引入额外 C++ 包装框架。库的具体版本、静态链接可行性、体积、Windows TLS/代理、认证和许可证随附要求须在构建验证中确认；本决定不代表这些已通过验证。

Coop 的接口按 bucket 行为划分：识别来源与修订、获取远端对象、读取确定修订的文件树、生成内容差异及可恢复发布。打开已有仓库不代表可以覆盖其本地修改；不默认执行强制重置或清理。历史 Manifest 解析也不因拥有 Git 库而自动成为已完成的兼容能力。
