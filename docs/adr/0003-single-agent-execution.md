# 单一代理一把抓开发

2026-10-28 人类决定取消编码代理与验收代理的分工：coop 的实现、测试编写、构建检查、真机验证、验收与状态回写由当前执行代理在同一会话内完成，同一时间仍只允许一个写入者。原「ChatGPT 调度、pi 编码、独立验收上下文」的结构不再使用，`AGENTS.md` 的执行分工随之改写。

理由是交接成本高于分工收益：调度者看不到完整证据，只能依赖执行方摘要，再靠定期巡检确认进度；而本项目当前的瓶颈是覆盖证据的广度（4149 份分母中只有 15 个包有运行事实），不是并行产出。单个代理持有完整上下文、直接读证据，省掉转述与反复对齐。

已知代价是失去独立验收的对抗性：同一上下文既写又验，容易自我一致地判过。补偿写进规则本身而非留给自觉——每条断言绑定可复核证据（命令、退出码、日志与文件摘要），报告区分本轮运行、静态检查、历史结果与未运行，真机写操作前后核对实际状态，且不用前一票的通过推断本票。出现「报告说通过、复核不通过」的实例，或真机写操作产生不可恢复的外部副作用时，重新引入独立验收；改回双代理须由人类明确同意。
