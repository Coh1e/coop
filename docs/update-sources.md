# 指定软件更新的来源准备

指定软件的 `coop update` 按安装记录或明确的 bucket 限定选择来源。Git bucket 在读取目标清单前走现有刷新流程。新清单声明的依赖继续纳入来源准备，每个来源在当前请求中只准备一次。本地目录直接提供清单。来源不可用、存在未提交修改或无法安全快进时，受影响的软件更新失败。

`coop update <app> --dry-run` 只读取共享仓库状态和远端分支广告。固定修订使用本地固定提交。跟踪分支的远端修订与共享 checkout 相同时才可用该工作树规划。修订不同或远端证据不足时退出 1，说明无法完成预览。预览不会 fetch 对象、写共享引用、刷新索引或迁移状态。

预览和执行 JSON 的 `source_revisions` 列出规划使用的 Git bucket 和提交 ID。执行事务也保存该字段。规划读取实际清单，校验清单摘要与共享安装事实，并在执行时复核修订。显式本地来源以清单摘要作为输入证据。

CTest 的 `update_source` 使用隔离 Git 远端和两个实际可运行的软件版本，覆盖远端变化、依赖来源、只读预览、固定修订和失败传播。bucket 回归覆盖刷新自身的快进、工作树与分叉保护。
