# 本地查询与 Git 刷新性能

日期：2026-10-25。任务：[T17 / #19](https://github.com/Coh1e/coop/issues/19)，父规格 [#2](https://github.com/Coh1e/coop/issues/2)。本文记录完整进程测量的方法、当前代码的实际结果、已证实瓶颈的优化，以及仍未达成的目标。所有夹具、缓存和日志都在项目内。

## 目标与判定

规格保留的性能目标：`version` 尽量低于 30ms，缓存命中 `list`/本地 `info` 低于 50ms，索引命中 `search` 低于 100ms。这些是待验证目标，不是任何机器上的保证。本页逐项报告实际值；超标项不隐藏，也不把目标当成已有成绩。

## 方法

- 每个样本测量完整进程启动到退出：`Process.Start` 到 `WaitForExit` 的挂钟时间，包含进程创建、加载、CLI 工作与退出；没有常驻服务、进程内计时或预热缓存填充。
- 每个命令执行 7 次，报告首跑 `first_ms` 与后续 `p50`/`p90`/`min`/`max`。首跑在夹具生成后立即进行，因此文件多半已在 OS 缓存中；它只表示"本进程首次"，不冒充系统级冷缓存。
- 进程创建地板：同一测量方式运行 `cmd.exe /d /c exit 0`，本轮 p50 为 30.6–33.2ms。`coop.exe` 的启动工作必须与这个地板区分，否则会把 Windows 进程创建和杀毒扫描算作 Coop 变慢。
- 数据：合成 Manifest 约 0.6KB，含 `version`、`description`、`homepage`、`architecture`，bucket 规模 200/1500/3000（约精选 bucket、Scoop Main、Main+Extras）。安装根 25/100 个包，每个包 1 个当前版本，每第 4 个包另有 2 个旧版本（无 Coop 记录，代表未接管安装）。
- bucket 读取分三种路径，分别报告：
  - **扫描**：未注册目录，每次查询读取并解析全部 Manifest；这是优化前 `search`/`info` 的唯一路径。
  - **本地索引**：`bucket add` 注册的本地目录，查询校验文件元数据指纹后读取 `.coop/index/<名称>.json`。
  - **Git 索引**：Git 快照，查询按已发布 revision 校验索引，不再对快照做 stat 扫描。
- Git 刷新：项目内 `file://` 仓库（1500 个 Manifest）经内嵌 libgit2 获取，分别测量首次、无变化、有变化，并记录耗时、libgit2 `received_bytes`、快照数量、索引哈希与注册表记录变化。默认套件保持离线；真实 HTTPS 的网络字节不在本轮运行范围。
- 环境：Windows 11 专业工作站版 N 10.0.26300；AMD Ryzen 7 8845HS（16 逻辑处理器）；64GiB 内存；KIOXIA-EXCERIA G2 NVMe SSD；PowerShell 7.6.5；CMake 4.4.4；Ninja 1.13.2；git 2.56.0.windows.3；`coop 0.1.0` Release 构建。基线提交 `eb6220f`，优化前测量使用该提交的构建。

结论：

- `version` 处于进程创建地板附近（地板 30.6–33.2ms，`version` 29.5–32.2ms），多次运行分别在目标两侧，不能宣称稳定低于 30ms。可执行文件本身的差距很小，继续压缩启动时间需要改变链接/分发方式，超出本票范围。
- 索引命中后 `search` 在 200/1500/3000 规模均低于 100ms；`info` 在 200/1500 低于 50ms，3000 规模 64.9ms 未达成，Git 1500 规模 52.5ms 本轮未达成（前两次 49.1/50.4ms，处于边界）。
- 未注册 bucket 仍按 Manifest 扫描，1500/3000 规模超标；这不是索引命中场景，不能当作已优化路径。
- `list` 只在 25 包规模达成 50ms；100 包 95.6ms 未达成。剩余成本主要是每包读取 Manifest、安装记录、持久化映射和旧版本目录证据，属于本地 I/O 与 JSON 解析。

## Git 刷新

本地 `file://` 仓库，1500 个 Manifest，内嵌 libgit2，无外部网络：

| 阶段 | 耗时 ms | libgit2 接收字节 | 本地工作 |
| --- | ---: | ---: | --- |
| 首次（夹具刚生成，数据未热） | 10610.0 | 146,762 | clone、导出 1500 文件快照、两次全量文件哈希校验、构建索引 |
| 首次（重复到新根，数据已热） | 1467.2 | 147,116 | 同上；同一操作在 OS 缓存热时的耗时 |
| 无变化 | 156.3 | 0 | `changed=false`，不新建快照，索引哈希不变；仅重写注册表中的 `received_bytes/changed` 元数据，`files`、`revision`、`path` 不变 |
| 有变化（新增 1 个 Manifest） | 1154.9 | 36,388 | 发布 1 个新快照、重建索引、旧快照内容不变 |

- 无变化刷新确实不做无关重建：快照数量不变、索引不重建、发布记录中的文件哈希表与 revision 不变。刷新仍会重新哈希当前快照以检测本地修改，这是安全校验而不是重建。
- 首次刷新在夹具刚写完与缓存已热时差异很大（10.6s 对 1.5s），说明该环境的首次文件访问与安全扫描占主导；本页不把任一数值当作所有机器的首次耗时。
- `received_bytes` 是 libgit2 传输回调统计的对象字节，`file://` 传输不代表真实网络。真实 HTTPS bucket 的网络字节和延迟未在默认套件运行；`tests/git-live.ps1` 只验证 HTTPS 可用性、无 git.exe 和代理/证书失败，不作为本轮字节证据。

## 已实施的优化

1. **可重建查询索引**（`src/catalog_index.cpp`）：bucket 显式 `add`/`update` 时把 Manifest 的搜索元数据写入 `.coop/index/<名称>.json`（紧凑 JSON），查询只读，不联网、不隐式刷新、不在查询期间写状态。
   - Git 来源以已发布 `path` + `revision` 校验；本地/未注册来源以 `(文件名, 大小, 修改时间)` 指纹校验。索引与来源不匹配、缺失或损坏时回退到原有 Manifest 扫描。
   - 索引只缓存可重建的展示/搜索字段；坏 Manifest 的诊断同样进入索引，查询输出字段与优化前一致。索引不参与卸载、清理或恢复决策。
   - 有变化刷新重写索引；无变化刷新不重写。索引写入失败只警告，bucket 仍保持已发布状态，查询回退扫描。
2. **`list` 旧版本证据延迟读取**（`src/versions.cpp`）：当前版本和受保护版本不再在每次查询中读取 Manifest/安装记录/目录树证据；只有确需报告的旧版本才计算。`tree_stamp` 只计算一次，Manifest 只读取一次并同时得到 SHA256 与解析结果。
3. **复用 CNG SHA256 provider**（`src/crypto.cpp`）：查询会哈希大量小记录，原实现每个文件都打开/关闭算法 provider；现在每进程打开一次。
4. **不变的行为**：索引不改变查询结果字段；`cleanup` 执行前仍重新验证旧版本证据；`bucket update` 的本地修改检测、快照导出/校验和无变化提前返回保持不变；没有常驻服务、后台刷新或全局环境改动。
